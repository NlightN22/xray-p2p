# Сертификаты сервера

Эта страница описывает текущее поведение `xp2p` при работе с TLS-сертификатами сервера.

## Источники сертификатов

Сервер может использовать один из двух источников:

- самоподписанный сертификат, который создаёт `xp2p`;
- готовые файлы сертификата и закрытого ключа.

Параметр `--cert-store` зарезервирован для хранилища сертификатов Windows, но в текущей версии он ещё не реализован.

## Добавление и замена

Если сертификат уже получен, например через Let's Encrypt, передайте файлы сертификата и закрытого ключа:

```console
xp2p server cert set --cert /path/to/fullchain.pem --key /path/to/privkey.pem
```

Если при установке или настройке сертификата не передан файл сертификата, `xp2p` создаёт самоподписанный сертификат для указанного имени сервера:

```console
xp2p server install --host edge.example.com
```

Перед принятием файлов `xp2p` проверяет входные данные:

- пути должны быть абсолютными;
- файлы должны существовать и читаться;
- сертификат и ключ должны быть корректными PEM-файлами;
- открытый ключ в сертификате должен соответствовать закрытому ключу.

Если в стандартном каталоге TLS сервера уже есть материалы сертификата, `xp2p server cert set` спросит подтверждение перед заменой.

## Проверка состояния

Текущее состояние сертификата можно посмотреть командой:

```console
xp2p server cert state
```

Команда показывает, настроен ли сертификат, действителен он или истёк, субъект, DNS-имена и IP-адреса из сертификата, даты действия, число оставшихся дней и признак самоподписанного сертификата.

## Удаление

В текущей реализации отдельной команды `xp2p server cert remove` нет.

Чтобы удалить роль сервера вместе со ссылками на TLS-материалы, удалите сервер:

```console
xp2p server remove
```

`server remove` удаляет Desired-входы сервера, Live- и LKG-артефакты сервера, файлы состояния сервера и каталог установки сервера, если он больше никем не используется. Если тот же корневой каталог использует клиент, общий каталог сохраняется.

Текущая реализация не удаляет `CONFIG_ROOT/tls/server` отдельным шагом. Скопированные `cert.pem` и `key.pem` исчезнут только если будет удалён весь корневой каталог конфигурации. Если корневой каталог общий с клиентской установкой, после `server remove` удалите устаревшие `CONFIG_ROOT/tls/server/cert.pem` и `CONFIG_ROOT/tls/server/key.pem` вручную, если они больше не нужны.

Дополнительно:

- `xp2p server remove --keep-files` оставляет файлы на месте и только проверяет цель удаления.
- Если серверный сервис запущен, остановите его перед удалением.

## Почему файлы копируются

Когда `xp2p` получает готовые TLS-файлы, он копирует сертификат и закрытый ключ в стандартный каталог TLS сервера:

- `CONFIG_ROOT/tls/server/cert.pem`
- `CONFIG_ROOT/tls/server/key.pem`

На Linux и OpenWrt стандартный корневой каталог конфигурации — `/etc/xp2p`, поэтому обычные пути такие:

- `/etc/xp2p/tls/server/cert.pem`
- `/etc/xp2p/tls/server/key.pem`

Копирование держит рабочие файлы внутри каталога, которым управляет `xp2p`. Благодаря этому запуск сервиса не зависит от временных путей загрузки, каталогов подготовки пакета и других мест, которые могут исчезнуть после настройки. Также это даёт сервису предсказуемые права чтения для файла закрытого ключа.

Исходные файлы после копирования не отслеживаются. Если `/path/to/fullchain.pem` позже обновится, копия в каталоге `xp2p` сама не изменится. После продления сертификата нужно снова выполнить `xp2p server cert set`, чтобы сервер начал использовать новые материалы.

## Когда обновляется сертификат

`xp2p server cert set` записывает TLS-файлы и создаёт запрос применения для сервера. Затем поток применения сервиса или `xp2p run` компилирует Desired-входы в Live-артефакты и запускает или перезапускает `xray-core` из Live-артефактов, когда это требуется.

Сертификат обновляется в таких случаях:

- `xp2p server install` создаёт или копирует TLS-материалы во время установки;
- администратор снова выполняет `xp2p server cert set`;
- сервисный поток применения обрабатывает созданный запрос применения.

В текущей реализации нет периодического обновления сертификатов. Для сертификатов от центра сертификации, например Let's Encrypt, настройте обработчик после продления, который выполнит `xp2p server cert set` после записи новых файлов.

## Дополнительно

Заменить существующие TLS-материалы без интерактивного вопроса:

```console
xp2p server cert set --cert /path/to/fullchain.pem --key /path/to/privkey.pem --force
```

Для неинтерактивных сценариев `--quiet` тоже отключает вопрос о замене и выполняет замену:

```console
xp2p server cert set --cert /path/to/fullchain.pem --key /path/to/privkey.pem --quiet
```

Если сертификат и закрытый ключ находятся в одном PEM-файле, передайте один и тот же путь в оба параметра:

```console
xp2p server cert set --cert /path/to/server.pem --key /path/to/server.pem
```

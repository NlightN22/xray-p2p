# Пайплайн нормализации

Эта страница определяет, как xp2p развивает сохраняемые данные, которыми владеет проект, без добавления schema version в пользовательские файлы и без цепочек миграций по версиям.

Пайплайн нормализации применяется к сохраняемым входным данным и файлам состояния, которыми владеет xp2p, например:

- TOML-конфигурация приложения.
- JSON-файлы состояния, например `dns-forward-state.json`.
- Будущие файлы метаданных, которыми владеет xp2p.

Он не применяется к Xray JSON. Xray JSON является внешним форматом времени выполнения и должен обрабатываться только компилятором и валидаторами Xray-конфигурации.

## Модель

Каждый доменный пакет владеет своими сырыми и каноническими моделями. Общий код нормализации предоставляет только универсальные примитивы.

```text
Raw decode
  -> Defaults
  -> Compatibility rules
  -> Validation
  -> Canonical model
  -> Optional canonical write
```

Код приложения должен использовать каноническую модель. Устаревшие поля и старый синтаксис должны интерпретироваться только внутри правил совместимости.

## Общий пакет

Общий пакет находится в `go/internal/normalize/` и содержит:

- `Report`: предупреждения, устаревшие поля, применённые правила и заметки.
- `Rule`: стабильное имя правила, описание, `DeprecatedSince`, `RemovedSince`, заметку об удалении и функцию применения.
- `Pipeline`: значения по умолчанию, правила совместимости, валидацию и построение канонической модели.

Общий пакет не должен знать доменные поля вроде `auto_forward`, `forward_owner` или `server.address`.

## Структура доменного пакета

Сохраняемые данные конкретного домена должны держать normalization-код рядом с доменом:

```text
go/internal/<domain>/
  <name>_raw.go
  <name>_canonical.go
  <name>_compat.go
  <name>_normalize.go
```

Сырая модель принимает текущий и устаревший синтаксис. Каноническая модель содержит только поля, которые разрешено использовать бизнес-логике приложения.

## Правила совместимости

Совместимость должна быть явной и ограниченной по времени. Правило должно задавать:

- `Name`: стабильный идентификатор, используемый в отчётах и тестах.
- `Description`: что делает правило.
- `DeprecatedSince`: первая версия xp2p, в которой старый синтаксис считается устаревшим.
- `RemovedSince`: первая версия xp2p, в которой старый синтаксис должен отклоняться.
- `RemovalNote`: короткая подсказка, чем заменить старый синтаксис.

Когда текущая версия xp2p больше или равна `RemovedSince`, правило должно отклонять удалённый синтаксис вместо его нормализации.

Не добавляйте `schema_version` в пользовательские TOML, JSON-файлы состояния или файлы метаданных для этой цели. Считайте старые поля устаревшим синтаксисом.

## Запись канонического формата

Обычное чтение не должно автоматически переписывать файлы. Файл записывается в каноническом формате только во время штатного пути записи для этого файла.

Например, файл состояния, загруженный из устаревшего синтаксиса, остаётся без изменений, пока команда не изменит и не сохранит это состояние. Сохранённый файл должен пропускать устаревшие поля и включать канонические поля.

Будущие явные команды нормализации смогут использовать тот же pipeline с режимами:

- `check`
- `normalize --print`
- `normalize --write`

## Файл состояния DNS Forward

`dns-forward-state.json` является первым JSON-файлом состояния, который использует этот подход.

Legacy-синтаксис:

```json
{
  "auto_forward": true
}
```

Канонический синтаксис:

```json
{
  "forward_owner": "dns-forward"
}
```

Правило совместимости:

- Если `forward_owner` задан, он является приоритетным источником.
- Если `forward_owner` отсутствует, а `auto_forward` равен `true`, значение нормализуется в `forward_owner = "dns-forward"`.
- Если `auto_forward` равен `false` или отсутствует, это нормализуется как отсутствие владения со стороны dns-forward.
- Если устаревшие и канонические поля конфликтуют, возвращается ошибка нормализации.
- Начиная с xp2p `0.2.8`, `auto_forward` отклоняется.

`dns-forward remove` использует только каноническое владение:

- Удаляет dnsmasq-запись домена.
- Проверяет, является ли это последним dns-forward доменом, который использует тот же forward listen port.
- Если это последний домен и `forward_owner == "dns-forward"`, удаляет xray forward.
- Если forward не принадлежит dns-forward, оставляет xray forward на месте.

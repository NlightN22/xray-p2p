# Server Certificates

This page describes the current server TLS certificate behavior.

## Sources

The server can use one of these certificate sources:

- A self-signed certificate generated by `xp2p`.
- A certificate and private key supplied as files.

Windows certificate store input (`--cert-store`) is reserved but is not implemented in the current release.

## Add or Replace

Use file-based certificates when you already have TLS material from a CA such as Let's Encrypt:

```console
xp2p server cert set --cert /path/to/fullchain.pem --key /path/to/privkey.pem
```

If no certificate file is provided during install or cert setup, `xp2p` generates a self-signed certificate for the configured server host:

```console
xp2p server install --host edge.example.com
```

`xp2p` validates file-based input before accepting it:

- Paths must be absolute.
- Files must exist and be readable.
- The certificate and key must be valid PEM data.
- The certificate public key must match the private key.

When TLS material already exists under the default server TLS directory, `xp2p server cert set` asks before replacing it.

## State

Check the currently configured certificate:

```console
xp2p server cert state
```

The state command reports whether a certificate is configured, whether it is valid or expired, the subject, SAN names, validity dates, remaining days, and whether the certificate is self-signed.

## Removal

There is no standalone `xp2p server cert remove` command in the current implementation.

To remove the server role, including its references to TLS material, remove the server role:

```console
xp2p server remove
```

`server remove` removes server Desired inputs, Live and LKG server artifacts, server state files, and the server-owned install directory when it is no longer used. If client files still use the same install root, the shared install root is preserved.

The current implementation does not remove `CONFIG_ROOT/tls/server` as a separate step. The copied certificate and key are removed only when the whole config root is removed because no other role still uses it. If the config root is shared with a client installation, remove stale `CONFIG_ROOT/tls/server/cert.pem` and `CONFIG_ROOT/tls/server/key.pem` manually after `server remove` if those files are no longer needed.

Advanced:

- `xp2p server remove --keep-files` leaves files in place and only verifies the removal target.
- Stop the server service before removal when it is running.

## Copy Behavior

When `xp2p` receives file-based TLS material, it copies the certificate and private key into the default server TLS directory:

- `CONFIG_ROOT/tls/server/cert.pem`
- `CONFIG_ROOT/tls/server/key.pem`

The default config root is `/etc/xp2p` on Linux/OpenWrt, so the default paths are:

- `/etc/xp2p/tls/server/cert.pem`
- `/etc/xp2p/tls/server/key.pem`

The copy keeps runtime files under the xp2p-owned config root. This makes service startup independent from temporary upload paths, package staging paths, and paths that may disappear after provisioning. It also gives the service predictable read permissions for the key file.

The source files are not watched after the copy. Updating `/path/to/fullchain.pem` later does not automatically update the xp2p TLS copy. Run `xp2p server cert set` again after a certificate renewal if the running server should use the renewed material.

## Apply Timing

`xp2p server cert set` writes the TLS files and creates a server apply request. The service/run apply flow compiles Desired inputs into Live artifacts and starts or restarts xray-core from Live artifacts as needed.

The certificate is updated when one of these happens:

- `xp2p server install` creates or copies TLS material during installation.
- `xp2p server cert set` is run again.
- The service/run apply flow processes the resulting apply request.

There is no periodic certificate refresh loop in the current implementation. For CA-managed certificates such as Let's Encrypt, schedule a renewal hook that runs `xp2p server cert set` after the CA client writes the new files.

## Advanced

Replace existing TLS material without an interactive prompt:

```console
xp2p server cert set --cert /path/to/fullchain.pem --key /path/to/privkey.pem --force
```

For non-interactive scripts, `--quiet` also suppresses the replacement prompt and proceeds with the replacement:

```console
xp2p server cert set --cert /path/to/fullchain.pem --key /path/to/privkey.pem --quiet
```

If the certificate and key are stored in a single PEM file, pass the same file to both options:

```console
xp2p server cert set --cert /path/to/server.pem --key /path/to/server.pem
```
